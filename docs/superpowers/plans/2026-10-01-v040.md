**Goal:** Deliver all ten accepted roadmap improvements, then publish and install a verified v0.4.0 from main.

**Architecture:** Keep SQLite reads and supported automation writes. Add shared query/date/output/mutation components at the existing library/CLI boundaries. **Tech stack:** Swift 6, ArgumentParser, GRDB, AppleScript/JXA, XCTest/Swift Testing, GitHub Actions, Bash, Homebrew.

## Shared contracts

- JSON schema version 1: every JSON response is an object with `schemaVersion: 1`, `success: Bool`, and `data` containing the command payload. Failures also contain `error: {code, message}`; partial results remain in data. Existing library serialization stays unchanged; CLI wraps it. Help/version/completion scripts remain their native text formats. Interactive pick with --json is explicitly rejected without writes; review supports JSON reports instead of text.
- Exit codes: 0 success, 1 invalid input/ambiguity/refused noninteractive confirmation, 2 runtime failure/partial failure/unhealthy required capability. Explicit user cancellation in an interactive session may return success with `applied: false`.
- Query sort keys: id/name/due/when/created/modified, optional leading minus for descending; stable ID tie-break. Positive --limit. --list narrows scope, --include-logbook adds history; defaults remain open lists for filter/views and visible search behavior.
- Mutation previews expose final field values, exact ID where applicable, assignments, tags, schedule, deadline, and undo capabilities. Add/template relative expressions remain expressions until execution; explicit scalar options override parsed/template values and tags merge as documented.
- Batch plans are schema-versioned local JSON documents containing operation, exact IDs, expected snapshots, requested changes, and result state. `--execute-plan PATH` confirms the whole plan before writes; --yes explicitly authorizes noninteractive execution. Reject mismatched options/duplicate IDs/stale snapshots. Persist results after each item and retry failed/pending items only, never prior successes. Generated plans are previews, not implicit authority.
- Undo capability matrix: single create/status/name/notes/deadline/tags and grouped supported status/tag changes are reversible; scheduling/headings/project moves require explicit warnings when not fully restorable. Retain journal entries after failed reversal, retain unreversed group members, and report storage errors without claiming reliable undo. Tests cover journal-write failure and every supported field.
