# clings v0.4.0 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for task implementation and independent specification/code-quality review. Use test-driven-development for behavior changes.

**Goal:** Deliver all ten accepted roadmap improvements, then publish and install a verified v0.4.0 from main.

**Architecture:** Keep SQLite reads and supported automation writes. Add shared query/date/output/mutation components at the existing library/CLI boundaries. Preserve existing command names while correcting unsafe or ambiguous behavior; JSON changes are versioned and documented in the minor release.

**Tech stack:** Swift 6, ArgumentParser, GRDB, AppleScript/JXA, XCTest/Swift Testing, GitHub Actions, Bash, Homebrew.

## Task 1: Query scope and strict dates (roadmap 6, 7)

Files: CLI query support and add/update/template/search/filter/views/list commands; FilterParser/FilterExpression/Todo; corresponding Core and CLI tests.

- [ ] Write failing tests for invalid dates/options, unknown fields/trailing DSL input, scheduled-start querying, query scope/sort/limit, and update preview.
- [ ] Run targeted tests and retain expected failing evidence.
- [ ] Implement shared strict date resolution and --parse-only update preview with no writes; invalid dates must fail before any mutation.
- [ ] Implement --list/--include-logbook/--sort/--limit for search/filter/views with explicit validation, deduplicated scope, and deterministic order. Preserve defaults and aliases. Add a scheduled-start field distinct from deadline.
- [ ] Run focused and full tests, self-review, commit only owned files.
- [ ] Independent spec review, resolve gaps, then independent quality review.

## Task 2: Safe deletion, retryable undo, and batch plans (roadmap 4, 5, 8)

Files: mutation/undo/bulk/pick commands, support; UndoStore and plan types; CLI/Core mutation tests.

- [ ] Write failing tests for default delete confirmation/refusal and --force; failed-undo retention; status restoration; batch exact-ID plans/partial results and grouped undo.
- [ ] Run tests to prove missing behavior.
- [ ] Retain API-supported cancellation for delete and say so consistently; no unimplemented Trash promise. Require confirmation, allow --force, and avoid accidental interactive writes in JSON mode.
- [ ] Remove undo entries only after success, preserve original status, journal supported fields. Expose unsupported schedule/heading/project reversals before writes; do not imply complete restoration.
- [ ] Support serialized batch plans from --dry-run --json and execution from an explicit plan using exact IDs, validation, conflict checks, per-item results, sequential official-API writes, and controlled retries. Record grouped reversible changes; retain un-reversed changes on undo failure.
- [ ] Run tests, self-review, commit owned files; spec review then quality review.

## Task 3: JSON/exit contracts, diagnostics, generated completions/docs (roadmap 2, 3, 9, 10)

Files: shared output/error layer/root command; all JSON-capable commands; DoctorCommand; CompletionsCommand; contract tests and documentation-generation checks.

- [ ] Write failing process-level JSON tests for success/empty/errors/ambiguity/partial failure/interactive commands; meaningful diagnostic exits; generated command coverage.
- [ ] Add a schema-versioned response contract and no text pollution on stdout with --json, including parser/runtime errors. Prompts/progress go to stderr; noninteractive JSON never silently writes based on ambiguous selection.
- [ ] Standardize exit status: success 0, usage/validation/ambiguity 1, runtime/partial-failure/unhealthy required capability 2. Make optional missing token a capability-specific warning rather than blocking read-only health.
- [ ] Diagnostics distinguish setup/database/runtime/token/automation capability, with an opt-in read-only automation probe and redacted support output; do not create or expose secrets in diagnostics.
- [ ] Generate static completions from ArgumentParser metadata, add local saved view/template completion where feasible, generate reference baseline and recursive help/example CI checks. Avoid hand-maintained command tables in scripts.
- [ ] Run tests/self-review/commit; spec review then quality review.

## Task 4: Release integrity (roadmap 1)

Files: release scripts, GitHub Actions, version metadata, Homebrew tap.

- [ ] Test release preflight against stale tag/version/missing ancestry/dirty source.
- [ ] Build a release procedure requiring clean current main, passing exact-commit checks, matching source version/tag, real GitHub archive checksum, assets/completions, tap update, and installed version/help smoke checks.
- [ ] Make release artifacts and notes reproducible; never move the already published v0.3.2 tag. Mark it superseded when v0.4.0 is available.
- [ ] Verify release script failure paths and CI workflow behavior.

## Task 5: Integration, documentation, and independent final review

- [ ] Independent spec review against all ten roadmap items, then adversarial quality review. Fix blockers and repeat affected checks.
